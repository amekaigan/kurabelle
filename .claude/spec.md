# クラベル 方針と決めたこと（仕様書）

作業ルール（進め方・A／B／C・成分表の写し方・楽天の規約）は `CLAUDE.md`。
ここには**サイトの方針と、ユーザーと決めたこと**を書く。どのスレッドで作業しても、ここに沿っていれば同じ作りになるようにするため。
新しく決めたことがあれば、その日のうちにここへ追記する（A：作業メモの更新）。

## 0. ルールの根幹：長い目で見た収益の最大化（2026年10月27日、ユーザーの指示）
- **迷ったら「長い目で見て収益がいちばん増えるのはどれか」で決める。** ルールを新しく作るとき・見直すときも、この基準で理由を書く。
- ただし、次は収益の前提なので、収益のために緩めない：薬機法（効果をうたわない）、ステマ規制（広告の表示）、楽天ウェブサービスとアフィリエイトの規約、成分表の正確さ。破ると、アフィリエイトの停止・検索での評価の低下・読者の信用の喪失で、収益がまとめてなくなるため。
- **ページは、間違った情報でない限り消さない。** 一度公開したURLは、検索での評価と「商品名＋成分」「AとBの違い」で来る人の入口を持っている。消して一覧へ転送すると、その検索の入口ごと失う。
  - 新しくページを作るときは、中身の薄いページを増やさない条件（成分は2商品以上、ブランドは3商品以上、比較は1商品につき近い3件）で選ぶ。**一度公開したページは、対象（成分・ブランド・2つの商品）がサイトに残っている限り、条件を下回っても残す。**
  - 消すのは C（先に理由を伝えて相談）。消すのが正しいのは、情報が間違っていて直せないとき、対象の商品が手に入らなくなり残す価値がないとき、ほかのページとまったく同じ内容になったとき。消すときも、近いページへ301で転送する。
  - **製造終了品もページを残す**（2026年10月27日、ユーザーの判断。商品名で調べに来た人を、いま買える近い商品へ回遊させるため）。商品データに `discontinued`（`date` 生産終了日、`label`・`url` 出典、`checked` 確認日）を書く。商品ページは「製造終了品」の案内と「成分が近い、いま買える◯◯」6件を上に出し、購入ボタンは出さない。カテゴリの一覧・点数の順位・比較・成分の集計・比較ツールには入れず、ブランドのページの下に「製造終了品」として並べる。生産終了の日付と出典は、メーカーの発表で確かめる。第1号はニベアメン モーニング10 クリアジェル（花王の製造終了品のお知らせ：2024年10月31日に生産終了）。
  - 手元のビルドは、新しく消えるページがあると止まる（`ALLOW_GONE=1` を付けたときだけ通る）。OKをもらうまで付けない。

## 1. 誰のためのサイトか（2026年10月16日に決定）
- **主な読者は、老いが気になり始めた30〜40代の男性**。悩みは、頭皮のにおい・髪のボリューム（薄毛）・ベタつき・シミ・乾燥。女性にも同じ悩みの人はいるので、締め出す書き方はしない。
- ユーザー本人がこの悩みを持つ当事者。「自分が使いたいサイト」が基準。
- **老眼の人にも読みやすく**：文字とボタンを大きくする。押せる所は高さ48px以上、本文は16px以上。小さい灰色の文字に大事なことを書かない。

## 2. 名前と表記
- サイト名「クラベル」、ロゴの横に小さく kurabelle。ドメインは kurabelle.com。
- 検索結果のタイトル：トップは「クラベル｜成分でくらべるシャンプー・スキンケア」、ほかは「〇〇｜クラベル」。

## 3. 見た目（2026年10月16日に決定）
- **方向性は「マーカー × 手書き」**：自分のノートにメモしていくようなイメージ。
  - 手書き風は**イラスト（SVG）の中だけ**。文字はすべて一般的なゴシック体（Noto Sans JP。2026年10月22日、ユーザーの依頼で Zen Kaku Gothic New から変更。癖が少なく読みやすいため）。
  - 手書きの絵は `tools/gen-hand.js`（roughjs）で作り、`src/hand.json` に入っている。各ページは使う絵だけを埋め込む。
  - 背景は方眼。線は薄く（`--grid:#EDEFE8`）。
  - **枠線の片側（左だけ・上だけなど）だけに色を付けない**（2026年10月22日、ユーザーの依頼。いかにもAIが作った見た目になるため）。区別は文字の色・背景・札で付ける。
  - 黄色は控えめ（`--hl:#F5DF7E`、`--hl-soft:#FCF6DE`、付箋 `--note:#FCF2C2`）。
- ページの上には、いつもロゴ・サイト名がある。右上のメニューは**三本線だけ**（存在感を出しすぎない）。
- 診断ツール（`/app/`）も、サイトと同じヘッダー・フッター・色で、**別のサイトに見えないように**する。

## 4. トップページの作り（2026年10月16日、A案に決定）
- 並び：検索 →「悩みから選ぶ」→「迷ったら診断」→「お気に入り」→「クラベルとは」（「詳しく見る」で `/about/` へ）。
- 呼び名はこの3つで固定：「悩みから選ぶ」（旧「気になり始めたことから」）、「お気に入り」（旧「あなたの棚」）、「クラベルとは」（旧「クラベルの約束」）。
- 「クラベルとは」の3つ：メーカー表示のとおりに載せる／どの商品も同じルールで採点（特定の商品を売り込まない）／不安をあおらない。
- お気に入りは見ている人のブラウザにだけ保存する（`localStorage` の `kb-fav`）。

## 5. 商品ページ（2026年10月16日までに決定）
- 上から：大きな商品画像 → 商品名（見出しは自然に折り返す）→ 区分・容量 → お気に入り・楽天市場で見る → 価格 → 説明・香り → 5段階の点数のグラフ → 全成分と役割。
- **商品画像は楽天から**、見る人のブラウザで読み込む（サイトに保存しない）。見つからないときは種類ごとの手書きの絵。まとめ売り（×6など）は避けて単品を選ぶ。
- **価格は小さく、一例として出す**：価格・送料込／別・店名と「◯月◯日◯時◯分時点の一例です。価格や在庫は変わることがあります。」。一覧では価格と「楽天市場」だけ。
- **値段が高い・安いの評価は書かない。**
- 説明・香りはメーカー公式の言葉をもとに短く（出典は `infoSource`）。効果をうたわない。
- パンくずは1行。商品ページでは最後の商品名を省く（見出しと重なるため）。
- **グラフをなるべく早く見せる**（2026年10月17日、ユーザーの依頼）：画像は少し小さく（幅300px）、お気に入りは画像の右上の星だけ。並びは 画像 → 商品名 → 楽天市場で見る・価格 → 点数のグラフ → 短い紹介文 → メーカーの説明 → 全成分。
- 商品ページのグラフの下に「それぞれの観点の見方」：観点ごとに点数・何が多いと高くなるか（処方の傾向として）・この商品で数えた成分。「◯◯寄り」はこの商品で点数が高い観点だと添える（2026年10月17日、ユーザーの依頼）。
- お気に入りに入れた・外したときは、星が一瞬大きくなり、画面の下に「お気に入りに追加しました／外しました」と出す（追加のときは「一覧を見る」でトップのお気に入りへ）。
- 診断結果のグラフには、いちばん重視している観点を5.0とした度合いの数字を付ける（掛け率そのものは出さない）。
- **画面の下に診断の案内を出す**（2026年10月17日、ユーザーの依頼）：トップと診断ページ以外。「◯◯の診断 →／7問・1分で、あなたに合う順に」。×で閉じると7日間出さない。ページ下の「迷ったら診断」が見えている間は隠れる。
- **404.html を必ず置く**（2026年10月17日）：ないと Cloudflare Pages は存在しないURLにもトップページを返し、相対リンクと組み合わさって巡回ロボットが無限にURLをたどる（1日約25万回の読み込みになっていた）。404.html のリンクは「/」から始める。
- CSS・JSのファイル名には版番号（`?v=`）を付ける。スマホに古いファイルが残って表示が崩れたため（2026年10月17日）。
- 全成分の表には、何番目か（全◯成分中）を出す。医薬部外品の有効成分は「有効成分として配合（全N成分）」。

- **ボリュームの悩み（2026年10月20日、ユーザーと決定）**：髪に残る成分（カチオン成分・シリコーン・油分）が多いと根元が寝やすい。シャンプーの診断で「ボリューム」を選んだら指通りの重みを×0.3。結果に「コンディショナーは使わない選び方もある。使うならコンディショナーの診断で『ボリューム』を」のひと言。ボリューム重視の人にコンディショナーをセットですすめない（紹介料のためにすすめない）。
- **商品ページの説明の出し方（同日）**：観点の見方は押すと開く一覧にし、普段は観点名・バー・点数だけ。説明を足すときは、開いた中に入れる。灰色の注記は増やさず、1か所1文にまとめる。

## 6. 点数と診断
- 点数は「成分表に何が入っているかを、決まったルールで数えたもの」。効果・使い心地ではないと、出す場所ごとに添える。数え方は `/about/scoring/` で公開する。
- **点数があるのはシャンプーと保湿クリーム**（2026年10月17日時点の本番）。ほかのカテゴリは成分表と役割だけを載せる。
- **コンディショナー・トリートメントの点数**：指通り・髪の補修・うるおい・仕上がりの軽さ・刺激の少なさの5観点。2026年10月17日にユーザーのOKで本番に反映。
- **コンディショナーの診断（案）**：7問（性別・年代・髪の悩み・仕上がりの好み・カラー/パーマ・髪の長さ・避けたい成分）。同時に「仕上がりの軽さ」の幅を広げ、さらさら派としっとり派で順位が入れ替わるようにした。作業用のコピー（`conditioner-quiz`）でユーザーの確認待ち（B）
- **育毛剤・頭皮用エッセンスには点数を付けない**（医薬部外品が多く、点数が効き目の順位に見えるため）。有効成分と表示どおりの効能を載せる方向。
- **点数のルールを変える・新しいカテゴリに点数を付けるのは B**（まとめて確認）。
- 診断は、シャンプー・保湿クリーム（・コンディショナーは確認待ち）。どれも7問（`QUIZ_N`）。診断のあるカテゴリは gen.js の `QUIZ` と、比較ツールの `Q_CAT`。
  - トップ以外の全ページの下に「迷ったら診断」を置く。診断のないカテゴリでは「準備中」と書き、2つの診断を近いほうから出す。
  - 診断を終えたら、まず診断結果を見せる（ランキングはその下。結果の下に「あなたに合う順のランキングを見る」）。
  - 診断の結果（相性ランキング）から、各商品のページへ移れる。画像と価格も一覧と同じく出す。
  - **診断の結果は「診断結果らしく」見せる**（2026年10月17日、ユーザーの依頼）：重み（掛け率）の数字は出さない。「◯◯重視タイプ」の名前、重視していることのグラフ、重視した観点ごとに「◯◯が入った商品がおすすめです」と言い切り、その下に**いまの上位3商品に実際に入っている、よく知られた成分の名前**（コエンザイムQ10・ナイアシンアミドなど）をマーカーの札で出す（「やっぱりね」と納得できるように。2026年10月17日、ユーザーの依頼）。表示名は app の `FAMOUS` でそろえ、数え方は変えない。入っていない成分の名前は出さない。控えめにした観点も1つ添える。「◯◯を選んだため」という理由の説明は出さない（ユーザーの判断）。保湿クリームで悩みが最も重い人は「シミ・ハリが気になるタイプ」のように悩みの名前でタイプを作る。効果を約束しない一文を必ず付ける。重みの計算方法は「点数のつけ方」のページでは公開を続ける。
- **未決（C）**：EUで使用禁止のジンクピリチオン（規則 (EU) 2021/1902）を含む商品を、合計点で−3にするか。書き方も含めてユーザーの返事待ち。

## 6-2. 採点のしくみ（作業のための覚え書き）
- 採点の計算と成分の辞書は `src/core.js` の1か所だけ。比較ツール（`app/index.html`）の中の写しは、ビルドのときに core.js で置き換わる（2026年10月17日〜）。
- 辞書に成分を足すと、既存の商品の点数も動く。足したら、前後の点数を比べて、変わった商品と理由を報告する（点数のルールの変更と同じくB）。
- 辞書は**1成分1行**で書く（2026年10月24日）。点数は辞書の行の代表名ごとに数えるため、別々の成分を1行にまとめると1種として数えられ、成分ページも1つにまとまる。同じ成分の表記ゆれ・出典の誤字だけを、その行の別名に足す。
- 2026年10月24日、未分類だった112成分のうち111成分を辞書に追加（ユーザーのOK）。点数が変わったのは24件（`.claude/reports/2026-10-24-dict.md`）。トリシルバリンNaは確かめられず未分類のまま。
- 2026年11月5日、未分類だった70種のうち67種を辞書に追加して本番に反映（ユーザーの依頼）。点数が変わったのは17件（`.claude/reports/2026-11-05-dict.md`）。同じ日に商品50件の追加で増えた54種も追加（点数が変わったのは追加した商品の6件）。トリシルバリンNa・イソヘキサデカン乳酸・アルキル-1,3-ジメチルブチルエーテルは確かめられず未分類のまま。「(A/B)/(C/D)」の形の成分名は1成分として読む。

- **保湿クリームの診断は、選んだ悩みがいちばん強く効くようにする**（2026年10月17日）：以前は「脂性肌」「さっぱり」を選ぶと、シミやハリの悩みより「軽さ」が重くなっていた。悩み（シミ・ハリ・肌あれ）は＋2、肌のタイプや使い心地の好みはそれより小さく。
- コンディショナーの診断も同じ考え方（2026年10月17日）：悩みは＋2.5、仕上がりの好み・髪の長さはそれより小さく。悩みを選んだ人のタイプ名は「ダメージが気になるタイプ」のように悩みの名前で作る。シャンプーも同じ形にした（2026年10月17日、ユーザーのOKで本番に反映）：悩みは＋2.5（ベタつき・ニオイは洗浄力＋1.5・頭皮ケア＋1、頭皮の乾燥はやさしさ＋2）、頭皮のタイプ・洗い上がりの好みはそれより小さく。偏りが小さいとき（重みの差0.6未満）は「バランスタイプ」。
- 保湿クリームの観点「美容成分」は「ケア成分（ビタミン類など）」と呼ぶ（男性には何のことか分かりにくいため）。
- 「クマ」は選択肢に入れない：成分表から数えられる決まった成分がないため。顔の明るさは「シミ・くすみ（顔の明るさ）」で扱う。

## 7. カテゴリ
- 点数あり：シャンプー、保湿クリーム・乳液。
- 点数なし：コンディショナー・トリートメント、育毛剤・頭皮用エッセンス、美容液、洗顔料、ハンドソープ、カラーリンス・白髪染め。
- 新しいカテゴリの商品は `data/pending.json` で待ち、10件たまったら公開する（2026年10月17日〜）。
  - 例外：育毛剤・頭皮用エッセンスの4件は、このルールの前に公開していたため、そのまま公開しておく（2026年10月17日、ユーザーの判断）。
- カテゴリ名に「育毛」などの効能の言葉を使うのは、医薬部外品の表示に合わせた分類名としてだけ。化粧品の商品に効能を書かない。

## 9. 商品を足すペースと順番（2026年10月17日に決定）
- **週50件**（ユーザーの判断。最初は多めに）。定期実行「クラベル｜商品の追加」が火・木・土に約17件ずつ足す。様子を見て件数を見直す。
- 手順は `CLAUDE.md` の「商品を追加する手順」どおり（2つの出典で一字一句照合、`tools/check.py`）。
- **出典のルール**（2026年11月5日、ユーザーの指示）：公式に全成分があれば公式の情報を載せる（2回取得は写し間違いの確認）。公式になければ、別々の販売店2か所を見比べて一致したものだけ載せる。同じサイトの2回取得だけの照合はしない。販売店が1か所しかなければ見送る。一致しないものは無理に入れず `data/skipped.json` に理由を残す。
- **商品を足す目的は、検索の入口を増やすこと**（2026年11月7日、ユーザーの指示）。商品ページ・成分ページ・ブランドページ・「AとBの違い」のページが、それぞれ「商品名＋成分」などの検索の入口になる。入口を多く作り、長い目で収益を最大化する（0章）。
  - **女性向けの商品も入れてよい。** メンズの候補が2つの出典で照合できず取れないときに、件数を減らして終わらせない。女性向け・男女兼用の定番品（売れ筋で検索の多いもの）で週50件を埋める。
  - 下の順番は「同じように取れるなら、どれを先にするか」の目安。メンズが取れないことを理由に、その回の件数を減らさない。
- **足す順番**（上から優先）：
  1. 読者（30〜40代の男性）が使う商品：メンズ・スカルプ系のシャンプー、メンズの保湿クリーム・乳液・オールインワン
  2. 待機中のカテゴリを10件にそろえる：美容液・ハンドソープ（そろうと自動で公開）
  3. コンディショナー・トリートメント（点数と診断があるので、件数が増えるほど診断が役に立つ）

## 10. 収益化の方針（2026年10月17日に決定）
- 楽天アフィリエイトは「数で支える」柱。商品を増やして「商品名 成分」のような細かい検索から人を集める。
- **単価の高い案件（アフィリエイトの仲介サービス）も扱う**（2026年10月17日、ユーザーがA8.net・afbに登録済み）：メンズの頭皮ケア・スキンケアの直販（定期購入）など。点数はほかの商品と同じルールで数え、紹介料で順位を変えない。楽天の情報（画像など）を使う商品には楽天以外の紹介リンクを付けないため、仲介サービスの商品は「楽天を使わない直販の商品」として別に扱う（画像は仲介サービスが用意したものを使う）。
- **メーカー直販の商品の載せ方**（2026年10月17日、ユーザーのOKで本番に反映）：
  - 商品データの `shop` に、仲介サービス（`asp`：a8／moshimo／accesstrade／afb）、テキスト用の広告リンク（`url`）、計測用の1×1画像（`pixel`）、商品画像（`img`、`assets/products/` に置く）を入れる。`shop` がある商品は楽天の画像・価格・リンクを一切使わない。飛び先がAmazonのときは `dest: "amazon"` を入れる（ボタンが「Amazonで見る」になる。2026年10月18日、U-MAで使用）。
  - 商品画像は、パッケージやメーカーの画像に宣伝文句（「頭皮環境改善」「◯◯評価」など）が入っていても、そのまま使ってよい（2026年10月18日、ユーザーの判断。楽天の商品画像も同じ）。サイトの文章で効果をうたわないルールは変わらない。
  - 商品ページは「PR」＋「公式サイトで見る」と、広告であることの一文。価格は載せない（キャンペーンで変わるため、公式サイトで確かめてもらう）。
  - **購入ボックス**（2026年10月24日、ユーザーの指定で本番に反映）：PRの札（今の大きさ）・ボタン（横幅いっぱい、縦に並べる）・短い説明文（「広告リンクです。紹介料は点数・順位に関係しません。価格は各サイトでご確認ください。」＋広告について）をひとつの枠に入れる。
  - **1商品に広告リンクを2つ**出してよい（2026年10月24日）。2つ目は `shop.also` に `{asp, url, pixel, dest}` で書き、Amazonを先に表示する。U-MAはAmazon（A8.net）＋公式サイト（アクセストレード、1本1,000円）。1本ならAmazon、定期なら公式が安かったため（10月24日時点）。楽天の情報を使う商品には付けない決まりは変わらない。
  - 案件の説明にある宣伝文（「薄毛・抜け毛対策に」など）は使わない。クラベルの文は成分表から数えたことだけ。
  - 成分表は公式サイトから2回読み込んで照合する（ほかの商品と同じ）。公式サイトに全成分がない商品は載せない。
  - 広告リンクは仲介サービスの「テキスト」の種類を使う（バナー用のリンクを文字に流用しない）。
  - 楽天で載せている商品を直販に切り替えるときは、楽天の表示をやめる（同じ商品に両方は付けられない）。スカルプDのシャンプーは切り替える方針（ユーザーの判断）。A8.netのテキストリンクが届いたら切り替える。
- 広告であることをはっきり示す（2023年10月からのステルスマーケティング規制）。楽天ボタンの横に「PR」、価格の下に一文（2026年10月17日、ユーザーのOKで本番に反映）。
- **購入ボタンは最初から出す・比べるページにも置く・クリックを記録する**（2026年11月10日、ユーザーのOKで本番に反映）：

  - 検索ロボットが楽天の問い合わせ枠を使わないよう、robots.txt で `/api/` を巡回の対象から外した。
- 計測：Cloudflare Web Analytics（クッキーを使わない無料のアクセス解析）とGoogleサーチコンソール（2026年10月17日にユーザーが設定。ドメインのプロパティ、サイトマップ送信済み）。数字は月1回、ユーザーが画面の写真を送る（自動で取りに行く手段がまだないため）。
