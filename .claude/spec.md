# クラベル 方針と決めたこと（仕様書）

作業ルール（進め方・A／B／C・成分表の写し方・楽天の規約）は `CLAUDE.md`。
ここには**サイトの方針と、ユーザーと決めたこと**を書く。どのスレッドで作業しても、ここに沿っていれば同じ作りになるようにするため。
新しく決めたことがあれば、その日のうちにここへ追記する（A：作業メモの更新）。

## 1. 誰のためのサイトか（2026年10月16日に決定）
- **主な読者は、老いが気になり始めた30〜40代の男性**。悩みは、頭皮のにおい・髪のボリューム（薄毛）・ベタつき・シミ・乾燥。女性にも同じ悩みの人はいるので、締め出す書き方はしない。
- ユーザー本人がこの悩みを持つ当事者。「自分が使いたいサイト」が基準。
- **老眼の人にも読みやすく**：文字とボタンを大きくする。押せる所は高さ48px以上、本文は16px以上。小さい灰色の文字に大事なことを書かない。

## 2. 名前と表記
- サイト名「クラベル」、ロゴの横に小さく kurabelle。ドメインは kurabelle.com。
- 検索結果のタイトル：トップは「クラベル｜成分でくらべるシャンプー・スキンケア」、ほかは「〇〇｜クラベル」。

## 3. 見た目（2026年10月16日に決定）
- **方向性は「マーカー × 手書き」**：自分のノートにメモしていくようなイメージ。
  - 手書き風は**イラスト（SVG）の中だけ**。文字はすべて見やすいゴシック体（Zen Kaku Gothic New）。
  - 手書きの絵は `tools/gen-hand.js`（roughjs）で作り、`src/hand.json` に入っている。各ページは使う絵だけを埋め込む。
  - 背景は方眼。線は薄く（`--grid:#EDEFE8`）。
  - 黄色は控えめ（`--hl:#F5DF7E`、`--hl-soft:#FCF6DE`、付箋 `--note:#FCF2C2`）。
- ページの上には、いつもロゴ・サイト名がある。右上のメニューは**三本線だけ**（存在感を出しすぎない）。
- 診断ツール（`/app/`）も、サイトと同じヘッダー・フッター・色で、**別のサイトに見えないように**する。

## 4. トップページの作り（2026年10月16日、A案に決定）
- 並び：検索 →「悩みから選ぶ」→「迷ったら診断」→「お気に入り」→「クラベルとは」（「詳しく見る」で `/about/` へ）。
- 呼び名はこの3つで固定：「悩みから選ぶ」（旧「気になり始めたことから」）、「お気に入り」（旧「あなたの棚」）、「クラベルとは」（旧「クラベルの約束」）。
- 「クラベルとは」の3つ：メーカー表示のとおりに載せる／どの商品も同じルールで採点（特定の商品を売り込まない）／不安をあおらない。
- お気に入りは見ている人のブラウザにだけ保存する（`localStorage` の `kb-fav`）。

## 5. 商品ページ（2026年10月16日までに決定）
- 上から：大きな商品画像 → 商品名（見出しは自然に折り返す）→ 区分・容量 → お気に入り・楽天市場で見る → 価格 → 説明・香り → 5段階の点数のグラフ → 全成分と役割。
- **商品画像は楽天から**、見る人のブラウザで読み込む（サイトに保存しない）。見つからないときは種類ごとの手書きの絵。まとめ売り（×6など）は避けて単品を選ぶ。
- **価格は小さく、一例として出す**：価格・送料込／別・店名と「◯月◯日◯時◯分時点の一例です。価格や在庫は変わることがあります。」。一覧では価格と「楽天市場」だけ。
- **値段が高い・安いの評価は書かない。**
- 説明・香りはメーカー公式の言葉をもとに短く（出典は `infoSource`）。効果をうたわない。
- パンくずは1行。商品ページでは最後の商品名を省く（見出しと重なるため）。
- 全成分の表には、何番目か（全◯成分中）を出す。医薬部外品の有効成分は「有効成分として配合（全N成分）」。

## 6. 点数と診断
- 点数は「成分表に何が入っているかを、決まったルールで数えたもの」。効果・使い心地ではないと、出す場所ごとに添える。数え方は `/about/scoring/` で公開する。
- **点数があるのはシャンプーと保湿クリーム**（2026年10月17日時点の本番）。ほかのカテゴリは成分表と役割だけを載せる。
- **コンディショナー・トリートメントの点数**：指通り・髪の補修・うるおい・仕上がりの軽さ・刺激の少なさの5観点。2026年10月17日にユーザーのOKで本番に反映。
- **コンディショナーの診断（案）**：7問（性別・年代・髪の悩み・仕上がりの好み・カラー/パーマ・髪の長さ・避けたい成分）。同時に「仕上がりの軽さ」の幅を広げ、さらさら派としっとり派で順位が入れ替わるようにした。作業用のコピー（`conditioner-quiz`）でユーザーの確認待ち（B）
- **育毛剤・頭皮用エッセンスには点数を付けない**（医薬部外品が多く、点数が効き目の順位に見えるため）。有効成分と表示どおりの効能を載せる方向。
- **点数のルールを変える・新しいカテゴリに点数を付けるのは B**（まとめて確認）。
- 診断は、シャンプー・保湿クリーム（・コンディショナーは確認待ち）。どれも7問（`QUIZ_N`）。診断のあるカテゴリは gen.js の `QUIZ` と、比較ツールの `Q_CAT`。
  - トップ以外の全ページの下に「迷ったら診断」を置く。診断のないカテゴリでは「準備中」と書き、2つの診断を近いほうから出す。
  - 診断の結果（相性ランキング）から、各商品のページへ移れる。画像と価格も一覧と同じく出す。
  - **診断の結果は「診断結果らしく」見せる**（2026年10月17日、ユーザーの依頼）：重み（掛け率）の数字は出さない。「◯◯重視タイプ」の名前、重視していることのグラフ、重視した観点ごとに「上位に来やすい商品の成分の特徴」を言葉で出す。控えめにした観点も1つ添える。「◯◯を選んだため」という理由の説明は出さない（ユーザーの判断）。保湿クリームで悩みが最も重い人は「シミ・ハリが気になるタイプ」のように悩みの名前でタイプを作る。効果を約束しない一文を必ず付ける。重みの計算方法は「点数のつけ方」のページでは公開を続ける。
- **未決（C）**：EUで使用禁止のジンクピリチオン（規則 (EU) 2021/1902）を含む商品を、合計点で−3にするか。書き方も含めてユーザーの返事待ち。

## 6-2. 採点のしくみ（作業のための覚え書き）
- 採点の計算と成分の辞書は `src/core.js` の1か所だけ。比較ツール（`app/index.html`）の中の写しは、ビルドのときに core.js で置き換わる（2026年10月17日〜）。
- 辞書に成分を足すと、既存の商品の点数も動く。足したら、前後の点数を比べて、変わった商品と理由を報告する（点数のルールの変更と同じくB）。

- **保湿クリームの診断は、選んだ悩みがいちばん強く効くようにする**（2026年10月17日）：以前は「脂性肌」「さっぱり」を選ぶと、シミやハリの悩みより「軽さ」が重くなっていた。悩み（シミ・ハリ・肌あれ）は＋2、肌のタイプや使い心地の好みはそれより小さく。
- 保湿クリームの観点「美容成分」は「ケア成分（ビタミン類など）」と呼ぶ（男性には何のことか分かりにくいため）。
- 「クマ」は選択肢に入れない：成分表から数えられる決まった成分がないため。顔の明るさは「シミ・くすみ（顔の明るさ）」で扱う。

## 7. カテゴリ
- 点数あり：シャンプー、保湿クリーム・乳液。
- 点数なし：コンディショナー・トリートメント、育毛剤・頭皮用エッセンス、美容液、洗顔料、ハンドソープ、カラーリンス・白髪染め。
- 新しいカテゴリの商品は `data/pending.json` で待ち、10件たまったら公開する（2026年10月17日〜）。
  - 例外：育毛剤・頭皮用エッセンスの4件は、このルールの前に公開していたため、そのまま公開しておく（2026年10月17日、ユーザーの判断）。
- カテゴリ名に「育毛」などの効能の言葉を使うのは、医薬部外品の表示に合わせた分類名としてだけ。化粧品の商品に効能を書かない。
